# 現在の方針

- 小さい単位で実装を進める
- 「仕様 → テスト仕様 → コード → テストコード → テスト」を細かく回す
- Runtime IDE として成立する構造を優先する
- Event / State・Command・Runtime 分離を重視する
- GPU Viewport は IDE コア構造として扱う
- Rust + egui を採用する
- WebView は IDE コアにしない
- WebView は Help / Docs / Tutorial / AI Chat などの Support Panel 用途で利用する
- WebView は Panel 単位で利用する
- WebView から IDE Core は Command 経由で操作する

# 現在の重要設計

## Event / State

- State = 現在状態
- Event = 状態変化通知
- UI は State を表示する
- Runtime / UI / 外部機能は Event を監視可能とする

## Command

- UI / API / WebView / 外部Runtime などを Command 経由で統一操作する
- WebView からの IDE 操作も Command 経由とする
- Undo / Redo を考慮する

## GPU Viewport

- IDE コア構造として扱う
- Docking UI と統合する
- MuJoCo / VRM preview / Simulation などを想定する

## WebView

- Core UI ではなく Support Panel として扱う
- egui ベース IDE の補助 UI とする
- Help / Docs / Tutorial / AI Chat 用途を想定する
- WebView からシーン切り替え等の IDE 操作を可能とする
- IDE 内部状態を直接変更せず Command API を通す

## v0.1.0 開発

Phase 0 で個別に成立確認した技術を、Framework 利用アプリから使用可能な最小 IDE 基盤へ統合する最初の開発版とする。

ゴールは、利用アプリが Framework 公開 API から一つの IDE Window / Dock を構築し、その中で Standard UI Panel、GPU Viewport Panel、Browser Panel を共存させられること。

主対象:

- Window / Dock / Panel の最小 Framework API
- 共通 Surface の Lifecycle / Input / Output
- GPU Viewport / GPU Surface 統合
- Browser Panel / Browser Surface / CEF OSR 統合
- Embedded Font / 日本語 UI
- Browser / GPU 共通 IME / Composition input model
- integration acceptance application
- 初期検証で記録した残課題の継続管理

Workflow、Event / State、Command、Runtime process 分離、Plugin 等の完成は v0.1.0 の必須範囲とせず、後続 v0.x で段階的に実装する。

詳細なスコープ・完了条件・API 設計制約は `docs/ja-JP/01_v0.1.0_開発概要.md` を基準とする。
