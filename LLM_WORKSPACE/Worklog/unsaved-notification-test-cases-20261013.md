# 未保存通知API・保存完了判定 テストケース（実装前）

対象: workflow-ide-framework develop
状態: 仕様確認・実装前テスト。実行結果は未検証。

## 基本規約
- FW、FW標準パネル、利用アプリは共通の未保存通知APIを呼び出す。呼び出し元が通知要否を判断する。
- 未保存通知は冪等で、プロジェクト未オープン時は無効。
- 保存の成功条件はアプリデータ、FW設定、project.tomlの全段階成功。途中失敗は未保存を保持する。
- 開く／閉じる／切り替え／終了は未保存変更を失わないよう確認を要する。
- 選択、スクロール、ホバーなど保存対象でない操作は通知しない。

## 実装前テストケース

| ID | 操作 | 期待結果 |
| --- | --- | --- |
| UNSAVED-TC-01 | プロジェクトなしで通知 | 未保存状態にならない |
| UNSAVED-TC-02 | プロジェクトありで1回通知 | 未保存になりタイトルに * |
| UNSAVED-TC-03 | 複数回通知 | 未保存のまま、副作用なし |
| UNSAVED-TC-04 | FWのWorkspace/Container/パネル配置を変更 | 共通API経由で未保存 |
| UNSAVED-TC-05 | FW標準パネルの保存対象データを変更 | 共通API経由で未保存 |
| UNSAVED-TC-06 | 利用アプリが公開APIを呼ぶ | 未保存となる |
| UNSAVED-TC-07 | スクロール・選択・ホバーのみ | 未保存にならない |
| UNSAVED-TC-08 | アプリ保存失敗 | 未保存を維持し失敗通知 |
| UNSAVED-TC-09 | アプリ保存成功、FW保存失敗 | 未保存を維持し失敗通知 |
| UNSAVED-TC-10 | アプリ・FW保存成功、project.toml保存失敗 | 未保存を維持し失敗通知 |
| UNSAVED-TC-11 | すべての保存段階が成功 | 未保存解除、* が消える |
| UNSAVED-TC-12 | 保存失敗後に再試行して全成功 | 未保存解除 |
| UNSAVED-TC-13 | 未保存で別プロジェクトを開く | 保存・破棄・キャンセルの確認 |
| UNSAVED-TC-14 | 確認でキャンセル | 元のプロジェクトと編集内容を保持 |
| UNSAVED-TC-15 | 未保存で終了 | 編集内容を失わない確認 |
| UNSAVED-TC-16 | 未保存状態でプロジェクトを開くダイアログ表示・取消 | 未保存状態とデータを維持 |
| UNSAVED-TC-17 | FW/アプリの保存が両方成功する前に通知状態を解除しようとする | 解除されない |
| UNSAVED-TC-18 | 保存途中に新しい変更通知が発生 | 新規変更が未保存として残る |

## 実装時の注意
- 既存の ProjectSession::complete_save は3段階の完了を確認する。共通通知APIはこの完了規約を迂回しない。
- 公開APIの所有者・パネルへの受け渡し方法、保存途中の新規通知の扱いは実装前に決定する。
- テストケースの作成と実装後のカバレッジ確認は分離する。
