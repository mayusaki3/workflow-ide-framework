# 未保存通知API：実装前テストケース（2026-10-13）

対象: workflow-ide-framework / develop

## 合意した基本方針
- FWが公開する未保存通知APIを、FW内部・標準パネル・利用アプリが共通利用する。
- 通知するかどうかは操作を実装した側が判断する。選択・スクロール等、保存対象外の操作は通知しない。
- 通知は冪等。保存完了の判定と未保存解除はプロジェクト管理側が行う。
- プロジェクト未オープン時の通知は、プロジェクトdirty状態に反映しない。
- 現行の ProjectSession / ProjectDirtyState（metadata/framework/application）を活用し、公開APIは利用側に内部区分を要求しない。
- プロジェクト切替・終了時に未保存確認を行い、保存・破棄・キャンセルを選べること。

## 既存実装の確認
- `ProjectSession` に `mark_metadata_dirty` / `mark_framework_dirty` / `mark_application_dirty` がある。
- `complete_save` はアプリ・FW・project fileすべて成功したときにdirtyを解除する。
- ウィンドウタイトルにはdirtyに応じた `*` 表示がある。
- FW/パネル/利用アプリ共通の公開通知APIは未整備。

## 実装順序
1. 公開通知APIとコントローラー接続（UNS-001〜003,008,009,010）。
2. FWのレイアウト変更検出（UNS-004,005）。
3. 標準パネルとSample Application（UNS-006,007）。
4. 切替・終了ガード（UNS-011〜017,019）。
5. Windows実機でケースを一件ずつ確認。

## 留意点
- アプリ独自パネルの保存対象かどうかはアプリが判断する。
- 保存操作の失敗や未保存データ消失を回避するガードが整うまでは、実データでの切替試験を避ける。
- 具体的な公開API名とコールバックの借用設計は実装時に決定する。
