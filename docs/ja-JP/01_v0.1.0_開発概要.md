# v0.1.0 開発概要

## 1. 位置付け

v0.1.0は、個別の技術検証で成立確認した要素を、Consumer Applicationから実際に利用できるWorkflow IDE Frameworkとして統合する最初の公開版である。

すべてのIDE機能を完成させることではなく、公開API、Project/Resourceのownership、永続化、Panel/Layout、標準Panel、通知等の基本契約を成立させることを目的とする。

## 2. Framework / Application責務

FrameworkはIDE共通機能とdomain非依存のmodel/action/APIを所有する。

Applicationはdomain model、domain validation、Application固有Project data、Resourceの意味、Runtime固有処理を所有する。

ConsumerがFramework内部実装をforkまたは直接変更することを前提としない。

## 3. v0.1.0対象

- Application / Window
- Dock / Panel
- Panel ID + Instance ID
- Panel Container / Layout
- Text Editor
- Log Viewer
- Tree Viewer
- Flow / Graph Editor
- Property Panel
- Controller Panel
- Language / Theme / Font
- Logging
- Project New / Open / Save / Save As
- Project-specific Framework settings
- Application-owned Project data boundary
- ResourceReference / Resource Registry
- File Resource Selector
- Application / Project / External Resource
- Resource import / move / rename / remove / delete
- Missing / Restored / Locate-Replace
- Unreferenced / Unregistered Resource search
- Resource watcher / root state
- Resource Operation Journal / Recovery
- Notification
- Application Command/Menu extension boundary
- Consumer向け統合Sample Application

Project/Resource/Panel Container/Notification等は、仕様確定後に実装・検証を進める。

## 4. Project

保存済みProjectの基本構造は次とする。

```text
<Project Root>/
├─ project.toml
├─ framework/
│  └─ framework_settings.toml
├─ resources/
└─ application/
```

FrameworkはProject lifecycleとFramework-owned stateを所有し、Applicationは `application/` 以下を所有する。

Window Geometry等のUser PreferencesはProjectから分離する。

## 5. Sample Application

Consumer向けExampleは機能別に分割せず `sample_application` へ統合する。

```text
cargo run --example sample_application
```

標準Panel、Language/Theme、Project/Resource/Notification等を同じApplicationへ順次統合し、Consumer integrationとGUI regressionを一つの実行対象で確認する。

既存の `stepX_...` Exampleは開発履歴・回帰検証用として当面保持する。Probe/診断ExampleはConsumer向けSampleへ統合しない。

## 6. Consumer validation

Frameworkの汎用性は単一Consumerへ固定せず、性質の異なるConsumerから確認する。

既存候補にはrobotics/simulation系Consumer、SansaCloth/SansaVRM系Consumerがある。Consumer固有domain機能をFrameworkへ持ち込まず、必要な共通境界だけをFrameworkへ還元する。

Consumer acceptanceは重要な検証だが、特定Consumerの内部構造をv0.1.0公開APIの基準にはしない。

## 7. Validation Capture

SansaCloth等から要求されるValidation Captureは、特定Consumer専用APIではなくFramework共通拡張として扱う。

Capture Target、Trigger、Event ID/Timestamp/Test ID等のCorrelation、Capture Set、Artifact保存を想定する。

v0.1.0公開を阻害しない範囲で拡張点を確保し、完全実装をv0.1.0 Release Gateにはしない。

## 8. 対象OS / 検証

対象OSはWindows / Linux / macOSとする。

- Windows: 実機検証
- Linux: VMで可能な範囲を検証し、物理環境必須項目は未検証可
- macOS: 環境を用意できない項目は未検証可

公開検証表は `○ / ✕ / ？` を使用する。未検証を非対応の✕として扱わない。

## 9. v0.1.0完了条件

1. Public APIとApplication/Framework責務境界が文書化されている。
2. Consumer向けSample Applicationが公開APIだけで構成される。
3. Standard Panelsと主要Framework設定をSample Applicationで統合確認できる。
4. Project formatとProject/Application ownershipが確定している。
5. Project New/Open/Save/Save AsとDirty/Save IDが成立する。
6. Resource Scope/Registry/Selectorと主要Resource操作が成立する。
7. Journal/Recoveryによりfilesystemとpersistent stateをまたぐ操作の異常終了を検出・解決できる。
8. Panel Container/Layout persistenceが成立する。
9. NotificationがFramework/Application双方から利用できる。
10. Unit testと統合GUI test仕様が実装に対応している。
11. Windowsでv0.1.0統合Sampleの必須検証を実施する。
12. Linux/macOSの未検証項目を？として公開できる。
13. README、利用ガイド、仕様、検証表が実装と矛盾しない。

細かなUIサイズ、Split比率、Notificationの視覚調整等は完了条件に含めない。

## 10. v0.1.0対象外

- 完全なPlugin Loader / dynamic Plugin API
- Remote Runtime
- AI Runtime / Debugger
- Project package/export
- Resource copy/cut/paste
- 高度なDock/floating window management
- Consumer domain固有editor/runtime
- 全OSで全項目を○にすること
- UIの細かな調整

将来機能を追加できるよう、v0.1.0 APIが不必要に拡張点を閉じないことは要求する。
