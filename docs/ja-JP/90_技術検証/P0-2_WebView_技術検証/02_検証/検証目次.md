# 検証目次

## 目的

P0-2 WebView 技術検証で実施する検証項目および進捗を管理する。

各検証の詳細な内容、実施結果、評価および設計判断は各 WV ドキュメントに記録する。

## 検証方針

本技術検証では、 Workflow IDE Framework における Support Panel 実現方式として WebView を利用可能か確認する。

WV-11 以降は、Window 埋め込み方式ではなく、Dock 上で Browser Surface / GPU Surface を成立させる Surface 共通アーキテクチャの技術成立性を確認する。

## 検証結果概要

### WV-00

Dock埋め込み方式は条件付き成功。
Dock矩形取得、移動・リサイズ検知、Child Window追従が成立した。

### WV-01

WebView表示成功。
WebView生成、URL表示、eframeとの共存が成立した。

### WV-02

Windows環境での egui 共存成功。
Dock移動、リサイズ、タブ切替、Child Window追従が成立した。

### WV-03

Linux Wayland環境では不合格。
build_as_child() が利用できず、Linux向け方式選定が必要と判定した。

### WV-04

Linux標準方式選定完了。
build_gtk() + gtk::Fixed 方式を採用した。

### WV-05

条件付き成功。
イベントループ統合は主因ではなく、GTK Host Window構成が有力候補と判定した。

### WV-06

Waylandで応答なし再現、X11で非再現を確認。
Wayland系要因の可能性が高まった。

### WV-07

条件付き失敗。
Panel同期自体は成立したが、GTK Toplevel Window表示中に応答なしが発生した。

### WV-08

完了。
GTK、WebKitGTK、WebView、イベントポンプ、Visibility制御では応答なしを再現できなかった。

### WV-09

完了。
WV-08で除外できなかった要素を切り分けたが、WV-09-06までの範囲では応答なしを再現できなかった。

同期処理単体では応答なしの主因を確認できなかったため、WV-10でWV-07再現時点との差分分析へ移行した。

### WV-10

完了。
Linux の応答なしは GTK / WebKitGTK を生成する構成に依存して発生することを確認した。

GTK / WebKitGTK を生成しない構成では応答なしは発生せず、eframe / egui / winit / Dock処理単体は主因ではないと判断した。

`WINIT_UNIX_BACKEND=x11` 指定下でも実際には Wayland Window として動作し、X11 親子化方式は成立しなかった。

GTK / WebKitGTK をホスト Window とする方式の検証を終了し、GTK を使用しない Linux WebView 実装方式の検討へ移行する。

### WV-11

完了。

Browser Surface は CEF OSR を用い、Native Browser Window を Dock へ埋め込むのではなく、描画バッファを egui Texture として Dock 内へ描画する方式で成立することを確認した。

Windows 実機では CEF OSR、Dock 表示、リサイズ追従、基本入力を確認した。Windows IME についても追加検証を行い、composition / candidate / commit の経路が成立した。最初の Space で候補ウィンドウが一度消えて再表示される残課題は正式合格条件と分離して記録している。

Linux VM / Wayland では、GTK / WebKitGTK Host Window 方式へ戻らず、同じ CEF OSR -> egui Texture -> Dock 経路で CEF OSR、Dock 表示、リサイズ追従が成立した。

Linux 実機および macOS は検証環境がないため `？` とし、非対応とは判定しない。

Browser Surface の実験用内部インターフェースを正式 API と分離して整理した。GPU Surface との共通化および正式 Surface API は WV-12 の結果を踏まえて判断する。

### WV-12

進行中。

WV-12-01 で GPU Surface の主検証方式として `wgpu` を選定した。

WV-12-02 では Windows 実機で wgpu off-screen Texture -> egui native Texture -> egui_dock の経路が成立し、Native Child Window を使用せず GPU 描画結果を Dock 内へ継続表示できることを確認した。

WV-12-03 では Windows 実機で Dock サイズ変更に伴う Texture 再生成、Visibility の Hide / Show、Surface の Destroy / Create、再生成後の継続描画を確認した。Resize 中は各サイズに応じて旧 Surface を破棄して新 Surface を生成し、明示的 Destroy 後は自動再生成せず Create 操作まで破棄状態を維持できることを確認した。

Linux VM、Linux 実機、macOS は未検証のため `？` とする。

次は WV-12-04 入力イベント転送検証を行う。
