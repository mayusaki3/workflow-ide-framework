# v0.1.0 統合テスト仕様

## 1. 目的

v0.1.0の公開判定を、個別の開発StepではなくConsumer向け `sample_application` と公開APIを基準に実施する。

既存のStep別テストはunit/regression資産として保持し、本仕様はそれらを置き換えるのではなく統合Acceptanceを追加する。

## 2. テスト層

1. Unit / model test: domain非依存logic、serialization、state transition、adapter。
2. Integrated Sample test: `cargo run --example sample_application` による複数機能同時GUI検証。
3. Consumer acceptance: Framework公開APIだけを利用する実Consumerで責務境界を確認。
4. OS verification: Windows / Linux / macOSの状態を `○ / ✕ / ？` で記録。

自動化可能なlogicを目視確認だけに依存させない。GUI/IME/native filesystem watcher等をcode coverageだけで合格扱いしない。

## 9. Code coverage

domain非依存logicはunit test対象とし、対象logicについて100% coverageを目標とする。

GUI renderer、native Window、IME、filesystem watcher、OS dialogはcoverage数値だけで判定せず、Integrated Sample/OS verificationを併用する。

標準候補:

```text
cargo llvm-cov --workspace --all-targets --summary-only
cargo llvm-cov --workspace --all-targets --html
```

実測前に推定coverage値を書かない。
