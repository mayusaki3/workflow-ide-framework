# 第1章 全体概要・アーキテクチャ

## 1.1 目的

Workflow IDE Framework “Kairi” は、Rust で IDE 型 Application を構築するための Application 組み込み型 Framework である。

Kairi は Application 固有機能を所有するのではなく、複数の IDE 型 Application に共通する Application / Project / Workspace / Panel / Resource / Common Services の基盤を提供する。

Consumer Application は Kairi の公開 I/F を利用し、domain 固有 model、validation、処理、表示内容を実装する。

## 1.2 全体構造

Kairi の仕様は、Application 開発者が上位レベルから順に実装できるよう次の構造とする。

```text
Consumer Application
│
├─ Application
│  ├─ Application metadata
│  ├─ Menu / Command
│  ├─ Status
│  ├─ About / Version
│  └─ Project
│
├─ Workspace
│  ├─ Workspace definition
│  ├─ Layout
│  └─ Panel placement
│
├─ Panel
│  ├─ Standard Panel
│  └─ Application Panel
│
├─ Resource
│
└─ Common Services
   ├─ Notification
   ├─ Logging
   ├─ Localization
   └─ Theme / Appearance
```

Project は Application が扱う管理データの単位であるため、Application と同じ実装段階で扱う。

Workspace は Application が利用可能な作業空間を定義し、Panel の配置を所有する。Panel instance 自体の所有と Workspace 上の配置は分離する。

## 1.3 Framework と Application の責務境界

Kairi は IDE 共通機能、Project lifecycle、Framework 管理データ、共通 UI 基盤および公開 API を所有する。

Consumer Application は次を所有する。

- Application 固有 domain model
- Application 固有 validation
- Application 固有 Project data
- Resource の Application 固有の意味
- Application 固有 Panel の内容
- Application 固有処理

Application 固有 Project data は Project の `application/` 以下を基本的な所有領域とし、Kairi はその意味や内部 file format を解釈しない。

## 1.4 機能仕様の段階

機能仕様の章番号は Consumer Application に提示する利用可能範囲として使用する。

- 第1章: 全体概要・アーキテクチャ
- 第2章: Application / Project
- 第3章: Workspace
- 第4章: Panel
- 第5章: Resource
- 第6章: Common Services

例えば「Kairi 機能仕様 第1章～第4章を利用可能」と指定された Consumer Application は、Application / Project / Workspace / Panel と、それらの章から参照される Public API / Event Reference を利用できる。

Reference 自体は機能解禁章として数えない。

## 1.5 Public API / Event Reference

各機能章では、Application 開発者から見た概念、設定方法、lifecycle、sequence、利用する API / Event 名を説明する。

Rust 型、引数、戻り値、payload、厳密な発火条件等は [Public API / Event Reference](Reference/README.md) に集約する。

## 1.6 実装状態との関係

仕様に記載された概念と、現行 v0.1.0 develop 実装の公開 I/F は区別する。

現行実装に存在する API は Reference に実装済みとして記録する。設計上必要だが公開 I/F がまだ存在しないものは、既存の型名を推測して仕様化せず「未実装」または「I/F 未確定」と明示する。

旧 Runtime / Workflow / GPU Viewport / Plugin 中心の仕様は Kairi 全体アーキテクチャの上位構造ではなく、再分類対象の旧仕様として保持する。
