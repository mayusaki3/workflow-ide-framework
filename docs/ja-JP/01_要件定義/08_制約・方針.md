# 制約・方針

Workflow IDE Framework “Kairi” の開発にあたり、以下の制約・方針を定める。

## 1. 要件分離

機能要件、アーキテクチャ要件、非機能要件を分離して管理する。

## 2. 特定用途への固定依存を避ける

特定のAI、ランタイム、クラウド、シミュレーション、ワークフロー等をKairiの必須用途としない。

## 3. Kairi本体の肥大化を避ける

利用アプリケーション固有のデータ、処理、エディター、ランタイム等は利用アプリケーション側の責務とする。

IDE型アプリケーションに共通する機能をKairi側の責務とする。

## 4. 長期運用を前提とする

保守、テスト、ドキュメント整備および拡張を継続可能な構造とする。

公開済みの利用アプリケーションへ不必要な破壊的変更を要求しないことを考慮する。

## 5. 公開境界を明確にする

利用アプリケーションはKairi内部実装の変更を前提とせず、公開されたインターフェースを通じてKairiの機能を利用する。

技術検証用インターフェースは正式な公開インターフェースと区別する。

## 6. 利用者が理解しやすいこと

利用アプリケーション開発者が、Kairiと利用アプリケーションの責務境界、機能の所有関係、保存対象を理解できる構造とする。

## 7. OS依存性を利用アプリケーションへ要求しない

Windows、Linux、macOS間の差異は可能な限りKairi側で吸収する。

環境を用意できない対象は未検証として管理し、未検証であることだけを理由に非対応とはしない。

## 8. HLDocS 準拠

ドキュメント管理はHLDocSに準拠する。
