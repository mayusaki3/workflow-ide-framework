# 非機能要件

Workflow IDE Framework “Kairi” は、以下の非機能要件を満たすこと。

## 1. 拡張性

利用アプリケーション固有機能や将来のKairi機能を、既存機能へ不必要な影響を与えず追加できる構造であること。

## 2. 再利用性

特定用途のアプリケーションに限定せず、複数のIDE型アプリケーションで再利用可能な構造であること。

## 3. 可搬性

Windows、Linux、macOSを動作対象とし、OSごとの検証状態を区別して管理できること。

未検証の環境を、検証なしに非対応として扱わないこと。

## 4. 応答性

パネル表示、レイアウト操作、状態更新等の通常のIDE操作を妨げない応答性を維持できること。

長時間処理または外部処理を追加する場合も、ユーザーインターフェース全体を不必要に停止させない構造を考慮すること。

## 5. 保守性

機能の責務境界を明確にし、長期的な保守、テスト、ドキュメント更新および拡張を継続できること。

## 6. 可読性

公開インターフェース、ユーザーインターフェースおよびドキュメントは、利用アプリケーション開発者が役割と責務を理解できる構造であること。

## 7. オフライン利用

Kairiの基本機能は、インターネット接続を必須とせず利用できること。

## 8. 導入容易性

利用アプリケーションからKairiを組み込み、基本機能を利用開始するまでの手順を明確にできること。

Sample Application等により基本的な利用方法を確認できること。

## 9. 技術依存の局所化

特定のAI、ランタイム、クラウドサービス、シミュレーター等をKairiの必須依存としないこと。

OSや描画基盤等への技術依存が必要な場合は、その影響範囲を可能な限りKairi内部へ局所化すること。
