# Kairi 全体概要

## 1. 目的

Workflow IDE Framework “Kairi” は、Rust で IDE 型アプリケーションを構築するためのアプリケーション組み込み型フレームワークである。

Project、Workspace、Panel、Resource、Menu / Command、Status、Logging、Localization、Theme 等、IDE型アプリケーションに共通する基盤をKairiが担当し、Consumer Applicationが固有機能の実装へ集中できることを目的とする。

特定のWorkflow、Runtime、AI、シミュレーション等をKairi自身の必須用途にはしない。これらはKairi上に構築されるConsumer Applicationの利用例または拡張対象として扱う。

## 2. 対象利用者

主な利用者は、IDE型UIとProject管理を持つRust Applicationを開発するConsumer Application開発者である。

利用例には、Runtime / Simulation IDE、AI / Asset Studio、Workflow Editor、GPU Viewportを持つ開発・検証Application等がある。

## 3. Framework / Consumer Application の責務

KairiはIDE共通機能とdomain非依存のmodel / action / Public APIを所有する。

Consumer Applicationはdomain model、domain validation、Application固有Project data、Resourceの意味、Runtime等の用途固有処理を所有する。

ConsumerがKairi内部実装をforkまたは直接変更することを利用条件としない。

## 4. 全体構造

Kairiの機能は、Consumer Applicationから見て次の順序で整理する。

1. Application / Project
2. Workspace
3. Panel
4. Resource
5. Common Services

ApplicationはKairiの最上位利用単位であり、ProjectはApplication levelで管理するデータとする。

WorkspaceはPanelの配置とLayoutを管理し、Panel instance自体はApplicationが所有する。

## 5. 対象OS

対象OSはWindows / Linux / macOSとする。

- Windows: 実機検証対象
- Linux: VMを含め検証し、実機必須項目は未検証として明示可能
- macOS: 環境を用意できない項目は未検証として明示可能

未検証は非対応を意味しない。検証状態は検証資料で区別する。

## 6. v0.1.0

v0.1.0は、Consumer ApplicationからKairiの公開I/Fを利用して基本的なIDE型Applicationを構築できる最初の公開版を目標とする。

機能ごとの現在状態は[目次](./目次.md)から要件・仕様・テスト仕様を参照する。将来要件や旧検討資料が存在していても、それだけをもって実装済みとは扱わない。
